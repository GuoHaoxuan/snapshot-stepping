# 天格（GRID）搜索：已核实的事实与未决项

搜索管线与仪器无关（`blink_search::search_day` 对 `Instrument` 泛型），天格只提供
自己的 `Chunk`/`Event`。四颗有事例产品的星共用一份实现，用类型参数 `Satellite`
区分。本文记录接入时在归档里**实测核实**过的事实，以及尚未定标、需要在跑数据中
迭代的判据。样本：GRID-04 2022-03-11、GRID-03B 2023-08-12、GRID-07 2024-03-15，
及各星各年的抽查。归档自带的两份《GRID科学数据说明》docx 都是 0 字节，格式全靠
读文件本身。

## 已核实（2026-09-05）

**归档布局。** `/gecamfs/Exchange/GSDC/missions/GRID/{GRID-02,GRID-03B,GRID-04,GRID-07}/`，
866 GB、16 万个文件。每星四个产品目录：

| 目录 | 内容 | 用途 |
|---|---|---|
| `fits7/YYYY/MM/DD/evt_vXX_YY/` | 逐过境事例文件 `Gxx_evt_YYMMDDhhmm_YYMMDDhhmm_vXX_YY.fits` | **搜索输入** |
| `fits8/YYYY/MM/DD/posatt_vXX_YY_ZZ/` | 同一批过境的 1 Hz 位姿，文件名时间段与事例文件一一对应（三天抽查 52 次过境全部配上且盖住 GTI） | 定位、姿态 |
| `fits5/NNNNN_YYMMDD_vXX_YY/` | 逐过境遥测监视（SiPM 电压、温度） | 不用 |
| `fits3/` | 观测计划 | 不用 |
| `source_orbit/` | STK 导出的 10 s 星下点表 | 只到 2023 年，不用 |

小写的 `grid-03b/ grid-04/ grid-07/`（2025-06）各只有 2 个子目录，是零星补交，未接入。

**观测日与曝光。** 事例产品的天数：GRID-02 75（2020-11-14..2021-03-08）、GRID-03B 789
（2022-03-11..2024-08-01）、GRID-04 527（2022-03-11..2024-08-22，2023-03..12 缺）、
GRID-07 195（2024-01-01..07-22）。**天格是逐过境记录的**：一天 1–21 次过境、每次
10–25 分钟，一天合计 0.5–10 小时（抽查 2023-01-01 0.49 h、2023-08-12 6.96 h、
2024-03-15 10.64 h）。多数小时没有文件，账本里记 `missing_data`、曝光为零；有文件
的小时曝光按 GTI 算。

**版本目录。** 一天常有多个 `evt_v*`，高版本过境更全（2023-08-12 的 `v03_00` 只有
1 次过境，`v03_01` 有 21 次；2023-06-06 是 6 对 16）。逐日最高版本全是 `v03_xx`
（没有一天以 v02 为最高）。归档自带的 `latest_evt.csv` 过时：GRID-03B 列 763 天而
实际 789 天，GRID-04 列 313 天而实际 527 天，GRID-07 没有这个文件。所以取字典序
最大的目录，不用 csv。

**事例文件结构。** `EBOUNDS`（97 道，GRID-02 是 98 道）、`GTI`（一行：本次过境起止）、
`EVENTS0..3`（4 个探测器）：`TIME`(D, s)、`PI`(I)、`DEAD_TIME`(B, µs，恒为 15)、
`EVT_TYPE`(B)。三天 52 个文件：探测器内时间零回跳、过境之间零重叠、事例全在 GTI 内。

**时间基准。** 头里 `DATE_REF = '2018-01-01T00:00:00.000'`，`TIME` 即自此起的秒数。
对账：`TIME = 132217726.086` ↔ `DATE_OBS = '2022-03-11T07:08:46.083'`，按 UTC 直接数
1530 天 + 25726 s = 132217726 s，完全一致；2017 年后无新闰秒。

**能道。** v03 是 97 道、5–2052 keV，对数分布（ch1 = 5–9，ch10 = 43–47，ch20 = 107–114，
ch50 = 421–436，ch97 = 1989–2052 keV）；GRID-02 是 98 道、7–2011 keV，同一道号差几个
keV；v02 产品是 200 道，但没有一天以它为最高版本。**阈值按能量定，不按道号。**
实测 v03 的谱从 ch5–7（21–29 keV）才起、ch12（56 keV）达峰，低端没有 GRM 那种噪声
堆，硬件阈值本身就切在 30 keV 附近。

**`EVT_TYPE`。** 实测只有 1 和 2：2 的 `PI` 恒等于最高道 97（中位=p10=p90=97），是
溢出/饱和一类的标记；GRID-03B 一天 6224 个（0.01%），GRID-07 一天 244 万个（4.6%），
且成簇（10 µs 内相邻的占 1.4%）。3 从未出现。`keep()` 只收 1。

**位姿。** `ORBIT_ATTITUDE` 1 Hz：`Q1..Q4`、角速度、`ATT_TYPE`、J2000/WGS84 坐标、
`Latitude/Longitude/Altitude(m)`、`POS_TYPE`。**位置并不总有**：抽查 32 天，
GRID-02 全程、GRID-03B 到 2024-01、GRID-04 到 2024-01 有位置（`POS_TYPE` 1/2）；
**GRID-03B 2024-04、GRID-04 2024-03/05、GRID-07 2024 年除 01-25 外全部 `POS_TYPE=0`，
经纬度和两套坐标全是 NaN，只剩四元数**。`source_orbit` 也不覆盖 2024 年。这些时段
的候选定不了位，只能丢并计数。

**计数率。** 单探测器约 400 c/s，四路合计约 1700 c/s，`DEAD_TIME` 15 µs/事例约合
0.65% 死时间。

**首次真实数据运行（2026-09-05，四星各一天）。** 账本曝光与归档 GTI 合计逐秒相等
（四天差值全为 0.0 s），没有过境的小时记 `missing_data`，GRID-07 的候选全部落入
`dropped_no_ephemeris`（位姿无位置解，符合预期）。但候选数荒谬：GRID-03B 一天 9213 个
（4776 个 fa≤1e-5，最亮 count=351 对 mean=37、fa=1e-199），GRID-07 28624 个，GRID-02
1641 个，GRID-04 455 个——且 99.6% 落在 |lat| ≥ 40°。

**根因：高计数率下读出成帧丢数。** 最亮候选周围 ±30 ms、1 ms 分格的四路计数长这样：

    0 0 0 0 0 0 0 0 0 27 78 52 79 64 0 0 0 17 80 69 74 60 0 0 0 0 0 0 0 0 67 73 71 88 ...

5–16 ms 的密集帧，帧间 3–12 ms 一个事例都没有，四个探测器同步。搜索窗落在帧内，
本底窗横跨帧与空洞，均值被拉低，帧内的普通计数就成了"暴发"。逐秒统计空洞占比
（四路合计连续 3 ms 无事例）对计数率：2–15 kc/s 的秒空洞占比中位 0.0–0.7%，到
辐射带（|lat| > 40°，5–75 kc/s）才成片出现；三天全部候选所在的秒率中位 5–75 kc/s、
空洞占比 40–80%，**率 < 3 kc/s 且无空洞的秒里一个候选都没有**。成帧的起始速率
各星不同：03B 到 15 kc/s 还干净，02 和 04 在 5 kc/s 附近就开始丢。（注意 3 ms
这个空洞定义在 < 1 kc/s 时没有意义——那里 Poisson 本身的间隔就常超过 3 ms，
表里低速率档的"空洞"是统计涨落，不是丢数。）

据此加了**读出空洞否决**（`search.rs` 的 `has_dead_gap`）：候选的本底窗
（±0.5 s，夹在所在 GTI 段内）里最长空段 L 在本地速率 r 下应有的计数 r·L 超过门槛
就否决，计入 `dropped_dead_gap`。

**全量首跑（1586 天）之后又收紧了两处。** 首跑用 r·L > 14（P < 1e-6）、r 取窗内
速率：03B 仍剩 19346 个候选、638 个显著，一半在 |lat| ≥ 40°，最亮的在 13–17 kc/s
的辐射带里——那里的形态是四路同时一个 1 ms 尖峰（86 个对本底 4/ms）后跟几毫秒
稀疏，四路合并后最长空段只有 0.6 ms，空洞判据抓不到；GRID-04 还有 count=8、
mean=0.00、窗内速率 2 c/s 的"候选"——成片丢数里的孤帧，窗内速率本身被压没了，
r·L 永远到不了门槛。改成：(1) r 取窗内速率与整次过境速率中的大者；(2) 门槛降到
r·L > 9.2（P < 1e-4，1 kc/s 时误否决期望约 1%）；(3) 再加一道**读出可信速率上限
5 kc/s**（`RATE_CEILING`，窗内与过境速率取大者）——各星成帧起始速率不同但都不低于
这个量级，而按首跑结果这道门对 |lat| < 40° 的显著候选一个不砍（03B 277/277），
砍掉的只有辐射带。计入 `dropped_high_rate`。

## 未决项

### 1. 低能阈 30 keV 未定标

取在硬件截止之上，等于"不额外砍"。是否需要更高的阈来压本底、或者更低的阈来保
灵敏度，要等第一批候选出来看窗内能谱再定。四颗星、两种道数方案都用能量阈，
跨星一致。

### 2. `EVT_TYPE = 2` 的语义未确认

`PI` 恒为最高道，形态像溢出/饱和标记，且成簇——GRID-07 上占 4.6%，明显多于
03B 的 0.01%，可能与该星的高压或阈值设置有关。目前当作非光子丢弃；若它其实是
"高于量程的真光子"，TGF 的硬谱正好会落进去，那就丢错了。要从天格团队拿定义。

### 3. 2024 年大半时段没有位置解

`POS_TYPE = 0` 的过境搜出的候选全部落入 `dropped_no_ephemeris`。这不是几个小时，
是 GRID-07 全程、03B/04 的 2024 年——约四百个观测日。补救只能靠 TLE + SGP4 自算
星下点（归档里没有 TLE；`source_orbit` 的 STK 表止于 2023-12），需要单独立项。
在那之前这些时段只能做判选 A 层、不能做闪电关联。

### 4. 跨午夜的过境

过境文件归到起始那一天。0 时的小时同时看前一天的目录，靠 GTI 判断是否有交集。
抽查的三天里没有跨午夜的过境，这条逻辑还没被真实数据踩过。

### 5. 四元数约定

`Q1..Q4` 哪个是标量部分不知道，`Attitude` 只存三个分量，这里按 SVOM 的做法存
`Q1..Q3`。搜索不用姿态，只是原样带出去；将来做视场判断时要先弄清约定。

### 6. 死时间未修正

15 µs/事例、约 0.65%，本底估计没扣。量级小。

### 7. 四个探测器合成一路

同型探测器，与 HXMT 的做法一致。但一颗立方星四面各一个探测器，TGF 来自天底方向
时未必四个都亮，分组是否更灵敏未评估（GBM 那边的经验是同型探测器合组更好）。

### 8. 只跑过单元测试，没跑过真实数据

本文写在第一次真实数据运行之前。三天样本、四颗星的接入全靠读文件核实，
`from_epoch`/`search` 的行为要用真实的一天来验证：小时账本里的 `missing_data`
数、曝光合计是否等于 GTI 合计、`dropped_no_ephemeris` 在 2024 年是否如预期。

### 9. 读出空洞的正解是当作 GTI 缺口

现在的否决只是把落在成帧区的候选丢掉。正解是把空洞当活时间缺口、让本底按真实
活时间归一，那样帧内的计数会对帧内的速率做检验，辐射带里的数据也能搜。但
`search_new` 的活时间夹取假设候选所在的一段 GTI 覆盖整个本底窗（为了内层循环
零开销），毫秒级的洞会把本底窗夹到一帧里、统计反而更差；要做得在核心里改成对
多段求交集长度。辐射带不是 TGF 的地方，先不做。

### 10. 首跑显著候选的构成：四分之三是穿过整星的带电粒子（判据已加，v3 已跑）

首跑 1586 天、速率门以下的显著候选（fa ≤ 1e-5）共 348 个。逐候选特征（几路探测
器亮、时间戳簇集、能谱、位置）把它们分成截然两群，分界在"最显著一格里同一时间
戳上的事例占比"：

- 261 个占比 > 0.35（中位 0.57，75 个为 1.0）：四路各一个事例、时间戳完全相同
  （跨探测器最小间隔 0），一格里就这四个加零星本底（计数中位 4），谱比本底硬得
  多（PI 中位比 3.8），经度均匀。这是穿过整星的带电粒子，四块 GAGG 同时响应、各
  留一个大沉积。它们 89% 在 |lat| < 40°——不是粒子在低纬更多，而是低纬本底安静
  （约 400 c/s），四个同戳计数才够 fa ≤ 1e-5；高纬同样的粒子淹在本底里。
- 87 个占比 ≤ 0.35：计数在几百微秒里铺开（时长中位 564 µs，计数中位 15），最小
  间隔在 4.77 µs 的时间戳分辨率量级，谱温和（PI 中位比 1.7），经度集中在
  120°E–180°（海洋大陆雷暴区 43%）。这是 TGF 该有的样子。

两群在占比 0.45–0.50 之间一个候选都没有。判据取 0.35（与 GBM 同），落在
`search.rs` 的 `MAX_SIMULTANEOUS_FRACTION`，计入 `dropped_simultaneous`。四路合成
一路搜索、没有组间符合可用，这道门是天格挡带电粒子的唯一手段。

v3 全量（2026-09-06）：候选 02/03B/04/07 = 51/2380/138/31，显著 4/36/10/3 = 53，
粒子否决 4/7797/15/51。53 个显著候选按时长又分两群：

- 29 个 < 500 µs：本底中位 331 c/s、谱硬（PI 中位比 3.0）、27 个在 |lat| < 40°，经度
  落在海洋大陆、非洲、印度、南美西北——雷暴区。最显著 6 个全在这里（03B，41–175 µs）。
- 24 个 ≥ 500 µs，大多顶在 1 ms 的搜索上限。宽窗轮廓（`grid_profile.py`，±30 ms
  按 1 ms 分格）量出真实时长 3–4 ms、超出 30–95 个计数、100 µs 格里没有尖峰（平滑），
  谱与本底一样（宽窗 PI 中位 14–32 对本底 12–29），四路均分。02/04/07 的显著候选
  几乎全是这一群，地理上全在高磁纬（|lat| 43–53° 的南北太平洋，以及 GRID-04 在
  澳大利亚以南 −28..−39°、经度 100–170°E——地磁南极偏向那边，磁纬同样高）。
  像高磁纬的相对论电子沉降（微暴），不像 TGF。TEB（TGF 的电子束）也会落在高磁纬，
  区分要看磁力线足点附近有没有闪电。**足点检验（2026-09-06）：** 用 IGRF 把 49 个显著
  候选的场线追到南北 100 km 足点（`scripts/grid_footpoints.py`），时刻前移电子飞行时间
  （近足点 400–900 km、1–3 ms；远足点 1.3–5.7 万 km、45–200 ms），近足点用 ±10 ms、
  远足点用 ±25 ms 跑 `blink wwlln --window-ms`（`scripts/grid_footpoint_tables.py`）。
  长群 22 个在两个足点都是 0 关联（偶然期望 0.00/0.01）；若它们是 TEB，按短群 26% 的
  关联率应有 5–6 个，P(0) ≈ 0.3%。短群在近足点关联 5 个，就是星下点那几个（近足点离
  星下点几百 km，在 800 km 半径内），远足点 0 个。结论：长群不是 TGF 的电子束，是磁层
  来源的电子沉降；不进 TGF 目录。
- 计数守恒检验（`grid_conserve.py`）排除了"积压事例重盖时间戳"的读出解释：若是重盖戳，
  ±100 ms 的总计数应等于本底（暴发的超出 = 周围的亏缺）；实测两群 ±100 ms 净超出
  与 ±10 ms 净超出之比中位 1.18（短）与 0.80（长），都是真多出来的计数。长群里 3 个
  例外（04 2022-04-14、07 2024-01-02、03B 2022-05-01）落在本底陡变或 8.7 kc/s 的
  高本底里，±500 ms 亏缺 300 个，不算干净。
- 短群里 2 个不是光子暴：03B 2023-08-08T19:53:50（一路探测器占 100%、PI 6）与
  2023-08-10T09:50:45（一路占 95%），后者同日 09:53:45 还有一个一路占 90% 的长群成员——
  同一天同一路探测器在闹。真暴发从下方照亮四路（03B 其余 27 个 det_frac_max 中位
  0.36）。已加单路占比上限 0.8（四个仪器共用，`blink_algorithms::detector_share`），计入
  `dropped_single_detector`；v4 之后的全量才含这条。

闪电关联（v8 定稿，2026-09-06，WWLLN ±5 ms / 800 km；四颗星全在 2024-12-31 的覆盖内）

v8 全量（权威，`gridrun/data`；v3/v5/v6/v7 存 data_v*.tar）：候选 02/03B/04/07 =

  候选。逐个看过（2026-09-06）：全在 03B，核心窗计数中位 7，同戳重数 3 的 20 个、

  7 个计数里 3 个共戳，按均匀铺在 50 个戳上算偶然概率约 1%，更像三路同时被粒子打中

  在覆盖内，`blink wwlln --instrument grid03b` 可以直接跑；偶然关联率对照是判断这
  87 个是真是假的下一步。
- 87 个 / 130 曝光日 ≈ 0.67/天，仍比 SVOM（1.25/天，面积大一个量级）显得偏多。
  最像真 TGF 的一例：GRID-03B 2022-10-04T00:09:56.543，79 µs 内 21 个、四路都亮、
  PI 中位 42–89（0.3–1.6 MeV）、本底 412 c/s、(153°E, 12°S) 珊瑚海。

### 11. 成帧丢数的物理起源与各星阈值

是 FPGA 缓冲溢出、还是传输链路的帧丢失，归档里看不出来；`DEAD_TIME` 恒为 15 µs
不反映它。各星起始速率不同（03B 15 kc/s，02/04 约 5 kc/s）可能对应固件版本。
要从天格团队拿读出设计。

### 12. 一个 0 字节的 posatt 文件

GRID-03B 2023-11-20 的 `posatt_v03_00_00/` 里有一个 0 字节文件，首跑时整天 17 个
小时因它记成 `corrupt_data`。已改成位姿文件读不出来就跳过并计入
`posatt_unreadable`；事例文件读不出来仍按 `corrupt_data` 处理。

### 13. 姿态解整段缺失：已把姿态改成可选（2026-09-06 定）

位姿文件的四元数会整段 NaN：GRID-02 2020-11-21 一天 92% 的行没有姿态（成段
154–177 s），GRID-03B 2022-10-01 有 6 段各 74 s。v3 全量里 82 个候选（44 天，3 个
显著：02 2020-11-21T21:32:19、03B 2022-07-18T15:19:25、03B 2022-10-01T12:34:00）
的姿态插成了 NaN，写进 JSON 变成 null，`blink wwlln` 读回时整颗星报错。

现在的处理：姿态表像位置表一样跳过 NaN 行；两张表都只在相邻有效采样相隔不超过
30 s 时插值（`interpolate_sampled`；位姿采样 03B/04/07 为 1 s、GRID-02 为 10 s，3 s
的门槛曾让 GRID-02 的候选全部定不了位），缺失段和过境之间不再拿两头连线——这也堵住了
位置表的一个隐患（位置解按文件整体缺失，混合的一天里候选会被插到两次过境之间）。
这些候选的时间和位置都是好的，只缺姿态，为此丢掉不合理：`Signal`/`UnifiedSignal`
的 `attitude` 已改成 `Option`（缺失时不写进 JSON，旧文件照常读回；全仓库没有下游
读姿态），四个仪器统一为"位置必须有、姿态可缺"，缺姿态的候选照留并计入
`without_attitude`。v7 里被丢的 82 个（显著 3 个）在 v8 起回到目录。
